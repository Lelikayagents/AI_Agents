# Формат исходника и карта шаблона

Заключение пишется в обычный текстовый файл (`.md`), а `scripts/render_opinion.py`
переносит его в фирменный `.docx`. Номера пунктов в исходнике **не пишутся** — их
проставляет Word из стилей шаблона. Это важно: если писать «1.1», «(a)» руками,
нумерация продублируется, а при добавлении пункта в середину всё поедет.

```bash
python3 scripts/render_opinion.py заключение.md -o "Заключение_ООО_Ромашка_ПРОЕКТ.docx"
```

## Шапка

Метаданные пишутся в начале файла, по одному ключу на строку. Русские и
английские ключи равнозначны.

| Ключ | Что заполняет | По умолчанию |
|---|---|---|
| `@наименование` / `@to_name` | адресат в строке «Кому» | `[наименование]` |
| `@адрес` / `@to_address` | адрес адресата | `[адрес]` |
| `@сокращение` / `@to_short` | сокращённое имя: `(далее – «Банк»)` | `[•]` |
| `@дата` / `@date` | строка «Дата» | `ПРОЕКТ` |
| `@кас` / `@re` | строка «Кас.:» — краткое описание сделки | `[краткое описание сделки]` |
| `@подпись` / `@closing` | текст перед подписью; `нет` — не выводить | `С уважением,` |

## Разметка текста

| Маркер | Стиль в шаблоне | Что это |
|---|---|---|
| `# ` | `SBLL1` | раздел: ВВЕДЕНИЕ, ДОПУЩЕНИЯ, ЗАКЛЮЧЕНИЕ, ОГОВОРКИ, АДРЕСАТ |
| `## ` | `SBLL2` | пункт (1.1, 2.1 …) |
| `### ` | `SBLL3` | подпункт ((a), (b) …) |
| `#### ` | `SBLL4` | под-подпункт ((i), (ii) …) |
| `##### ` | `SBLL5` | следующий уровень (в заключениях нужен редко) |
| `> ` | `BodyText` | абзац без номера (вводная фраза раздела) |
| `>> ` | `BodyText2` | продолжение пункта отдельным абзацем, с отступом |
| `- ` | `BodyText` + нумерация | пункт перечня документов в приложении |
| `-- ` | то же, уровень 2 | вложенный пункт перечня |
| `@@приложение Название` | `SBLSchL1` | новое приложение с разрыва страницы; Word сам напишет «Приложение 1», «Приложение 2» |
| `@@часть Текст` | без стиля | подзаголовок внутри приложения («Часть 1. Заемщик») и начало нового перечня с номера 1 |
| `@@разрыв` | — | разрыв страницы |
| `**текст**` | полужирный | выделение внутри абзаца |

Подпись (`С уважением,`) выводится автоматически перед первым приложением, а если
приложений нет — в самом конце.

Каждая `@@часть` и каждое `@@приложение` начинают нумерацию перечня заново с 1 —
скрипт для этого создаёт отдельный экземпляр списка в `numbering.xml`.

## Что должно остаться в квадратных скобках

Шаблон намеренно использует два разных знака, и их нельзя смешивать:

- `[текст]` — **опциональный или альтернативный блок**: включается или удаляется в
  зависимости от сделки (`[и управляющей компании Заемщика]`, `[Договоры залога …]`).
- `[•]` — **факт, который должен подставить юрист**: дата, номер, ФИО, наименование.

Оставлять `[•]` в проекте — нормально и правильно, если факт ещё не подтверждён
документом. Заменять `[•]` на правдоподобное значение «чтобы красиво» — нельзя:
именно из таких подстановок берутся заключения, подтверждающие несуществующие
доверенности.

## Пример исходника

```markdown
@наименование: ПАО «Банк Пример»
@адрес: 123112, г. Москва, Пресненская наб., д. 10
@сокращение: Банк
@дата: ПРОЕКТ
@кас: Договор купли-продажи 100% доли в уставном капитале ООО «Ромашка»

# ВВЕДЕНИЕ
## Мы выступали в качестве консультанта по российскому праву в связи с заключением Договора купли-продажи доли.
## Настоящее заключение предоставляется в отношении (1) правоспособности и полномочий Продавца и (2) действительности Договора купли-продажи доли.

# ДОПУЩЕНИЯ
> Для целей предоставления настоящего заключения, с Вашего согласия и без дополнительной проверки мы сделали следующие допущения:
## Документация
### все Документы были подписаны лицами, указанными в качестве подписавших их лиц;
## Правоспособность
### каждое лицо, указанное в качестве стороны любого из Документов:
#### является юридическим лицом, надлежащим образом учрежденным; и
#### обладает правоспособностью на заключение Документов.

# ЗАКЛЮЧЕНИЕ
> На основании и с учетом изложенного выше мы пришли к следующим выводам:
## Правоспособность и полномочия Продавца
### Продавец зарегистрирован в качестве общества с ограниченной ответственностью в соответствии с российским законодательством.

# ОГОВОРКИ
> Настоящее заключение приводится со следующими оговорками:
## Общие положения
### Ссылки в настоящем заключении на законодательство Российской Федерации должны рассматриваться как ссылки на действующие законы.
>> Мы не даем заключение относительно возможного толкования конкретных положений законодательства судами Российской Федерации.

# АДРЕСАТ НАСТОЯЩЕГО ЗАКЛЮЧЕНИЯ
> Настоящее заключение адресовано исключительно Вам и предоставляется для Вашего использования в связи с Договором купли-продажи доли.

@@приложение Перечень документов
@@часть Часть 1. Продавец
- Копия устава Продавца, утвержденного решением [•] от [•] года;
- Выписка из ЕГРЮЛ № [•] от [•] года в отношении Продавца.
@@часть Часть 2. Общество
- Копия устава Общества от [•] года;
- Список участников Общества по состоянию на [•] года.
```

В результате Word пронумерует разделы 1–5, пункты 1.1, 2.1, подпункты (a), (b),
под-подпункты (i), (ii), а заголовок приложения выведет как «Приложение 1».
Перечни в каждой части начнутся с 1.

## Карта стилей шаблона (`assets/template.docx`)

Нумерация зашита в стили, а не в абзацы:

- `SBLL1` → список `numId 16`, формат `1.` / `1.1` / `(a)` / `(i)` по уровням;
  `SBLL2`–`SBLL9` наследуют его через `basedOn`, меняя только уровень.
- `SBLSchL1` → список `numId 15`, формат `Приложение %1` — поэтому заголовок
  приложения нельзя набирать вручную как «Приложение 1».
- Перечни документов — `BodyText` с прямой нумерацией (`%1.`), образец в шаблоне —
  `numId 17`; скрипт клонирует его абстрактный список для каждого нового перечня.
- Шапка — таблица из трёх строк в начале документа; колонтитулы и разметка
  страницы живут в `sectPr` и переносятся из шаблона без изменений.

Скрипт при запуске проверяет, что нужные стили в шаблоне есть. Если фирма обновит
шаблон и переименует стили, будет понятная ошибка, а не документ со сбитой
нумерацией.
